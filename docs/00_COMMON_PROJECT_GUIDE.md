## 2. Coursework Goal & Problem Definition

The project is based on the **FActScore** benchmark for automated fact-checking.

The dataset contains atomic factual propositions extracted from biographies generated by ChatGPT. Each fact is paired with retrieved Wikipedia passages (retrieved using BM25).

The classification task is to determine whether each atomic claim is supported by the Wikipedia passages:
```text
S  = Supported
NS = Not Supported
```

The raw dataset contains three human annotations:
```text
S  = Supported
NS = Not Supported
IR = Irrelevant
```

During binary evaluation in `factchecking_main.py`, `IR` is automatically mapped to `NS`:
```python
converted_label = "NS" if example.label == "IR" else example.label
```
Therefore, our models must strictly predict only `"S"` or `"NS"`. Never predict `"IR"`.

The coursework requires two deliverables:
```text
1. PDF written submission (Report & Error Analysis)
2. factcheck.py (The ONLY code file submitted)
```

### Strict Submission Rules:
1. **Never modify `factchecking_main.py`**: The examiner runs their own copy of `factchecking_main.py`.
2. **Never modify the files in `data/`**: Keep `dev_labeled_ChatGPT.jsonl` and `passages_bm25_ChatGPT_humfacts.jsonl` untouched.
3. **Single Code File Rule**: All models, helpers, preprocessing, pruning, and analysis code must live inside `factcheck.py`. Do not create separate runtime `.py` or `.ipynb` modules that `factcheck.py` depends on.
4. **Required Runtime Commands**:
   ```bash
   python factchecking_main.py --mode word_overlap
   python factchecking_main.py --mode entailment
   ```
   Both commands must run cleanly and report the verified accuracy matching the report.

## 5. Dataset Findings from Exploratory Data Analysis (EDA)

Real data inspection reveals the following structural properties:

| Metric / Property | Dev Set Value | Analysis & Implication |
| :--- | :--- | :--- |
| **Total Biographies** | 31 documents | Evaluation cohort generated by ChatGPT. |
| **Total Atomic Facts** | 221 facts | The unit of fact-checking is an atomic claim. |
| **Original Label Counts** | 112 S, 93 NS, 16 IR | 50.7% S, 42.1% NS, 7.2% IR. |
| **Binary Converted Labels** | 112 S (50.68%), 109 NS (49.32%) | **Balanced 50/50 binary task**. Baseline random guess is ~50%. |
| **Average Fact Length** | 6.76 words (min: 4, max: 14) | Claims are concise propositions (e.g., *"Marianne McAndrew is an actress."*). |
| **Passages per Fact** | 3.13 passages (min: 2, max: 5) | Each claim is linked to 2–5 candidate Wikipedia chunks. |
| **Average Passage Length** | 141.13 words (min: 2, max: 211) | **Extreme Length Asymmetry**: Passages are ~20× longer than claims. |
| **Data Quality & Anomalies** | 0 missing, 0 empty, 1 duplicate | The claim *"Cleveland is in Ohio."* appears twice with conflicting annotations (`IR` and `S`). When `IR` $\rightarrow$ `NS`, this text has conflicting ground truths. |

> **Key Theoretical Takeaway**: The 20× length asymmetry explains why symmetric metrics like Jaccard $\frac{|F \cap P|}{|F \cup P|}$ fail (the denominator is flooded by passage words). Asymmetric **Word Recall** $\frac{|F \cap P|}{|F|}$ measures claim grounding directly without passage length distortion.

## 6. End-to-End Coursework Architecture

```text
Phase 0: Environment & Framework Setup
   ↓
Phase 1: Dataset Investigation & EDA (Computed in code, logged in tables/figures)
   ↓
Phase 2: Baseline Models (Random Guess ~50%, Always Supported 50.68%)
   ↓
Task 1: Word Overlap Classifier (40 Marks)
   - Preprocessing Ablation (Raw -> Lowercase -> Stopwords -> Stemming -> Numeric Integrity)
   - Similarity Metric Comparison (Recall vs Jaccard vs Dice vs TF-IDF)
   - Multi-Passage Max Aggregation
   - Systematic Threshold Tuning (0.40 to 0.90) & 5-Fold Cross-Validation
   - Target: >= 75%, Achieved: 85.07%
   ↓
Task 2: Textual Entailment with DeBERTa-v3 (40 Marks)
   - Passage Preprocessing & Sentence Splitting (spaCy sentence segmentation)
   - DeBERTa-v3 Inference on Premise-Hypothesis pairs
   - Decision Strategies: Discrete Argmax vs Continuous Probability Thresholding vs Margins
   - Word-Overlap Pruning (Skip DeBERTa on low-overlap sentences for speed and noise reduction)
   - Memory Safety (torch.no_grad, tensor deletion, gc.collect)
   - 5-Fold Cross-Validation for optimal pruning (gamma) and entailment (tau) thresholds
   - Target: >= 83%, Aim: 88–92%+
   ↓
Task 3: Qualitative Error Analysis (20 Marks)
   - Automated Extraction of all False Positives (FP) and False Negatives (FN)
   - Manual Inspection of >= 10 FP and >= 10 FN
   - 3–4 Fine-Grained Linguistic & Semantic Error Categories
   - Aggregate Frequency Statistics
   - 3 Detailed Case Studies with Explanations & Future Improvements
   ↓
Phase 6: Final Comparison & Submission Testing
   - Comparative Performance Table (Baseline vs Word Overlap vs Entailment)
   - Verify `python factchecking_main.py --mode word_overlap`
   - Verify `python factchecking_main.py --mode entailment`
```

## 8. Git Collaboration & Branch Agnostic Policy

- **No hardcoded branch dependencies**: Anyone can develop and test on any branch (e.g. `main`, `develop`, feature branches, or personal branches).
- **Code Ownership within `factcheck.py`**:
  - Task 1 edits focus on `WordRecallThresholdFactChecker` and lexical helpers.
  - Task 2 edits focus on `EntailmentModel`, `EntailmentFactChecker`, and inference/pruning helpers.
  - Shared imports and base structures should be modified cooperatively.
- **Pre-Merge Rule**: Always verify both execution commands before committing:
  ```bash
  python factchecking_main.py --mode word_overlap
  python factchecking_main.py --mode entailment
  ```

## 9. Coding Standards

1. **Short, Simple, Human-Style Comments**:
   - Write concise comments for big tasks and sub-components (e.g. `# Task 1: Preprocessing`, `# Step 2: Stemming`).
   - Avoid long, essay-like, or robotic comments.
   - Do not use emojis in code or comments.
2. **Clean & Understandable Code**:
   - Use descriptive variable names (`fact_tokens`, `passage_sentences`, `overlap_score`).
   - Use vectorized NumPy / PyTorch operations where appropriate.
   - Free memory explicitly in neural inference to prevent Out-Of-Memory (OOM) crashes.
