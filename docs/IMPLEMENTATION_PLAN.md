## 1. Executive Summary & Problem Formulation

### 1.1 Coursework Context & Operational Pipeline
This coursework is grounded in the **FActScore** benchmark (*Min et al., EMNLP 2023*), which evaluates the factual precision of biographies generated by Large Language Models (LLMs), specifically ChatGPT, against authoritative Wikipedia evidence.

```
+---------------------------------------------------------------------------------------------------------+
|                                        FACT-CHECKING PIPELINE                                           |
|                                                                                                         |
|   ChatGPT Biography  ──>  Atomic Claims (Hypotheses)                                                    |
|                                 │                                                                       |
|   Wikipedia Corpus   ──>  BM25 Passages (Premises)                                                      |
|                                 │                                                                       |
|                                 ▼                                                                       |
|                     +───────────────────────+                                                           |
|                     |   Classifier Engine   |                                                           |
|                     +───────────────────────+                                                           |
|                     | Task 1: Lexical (BOW) | ──> Score >= theta  ──> S / NS (Target >= 75%)            |
|                     | Task 2: Neural (NLI)  | ──> Score >= tau    ──> S / NS (Target >= 83%)            |
|                     +───────────────────────+                                                           |
|                                 │                                                                       |
|                                 ▼                                                                       |
|                     +───────────────────────+                                                           |
|                     | Task 3: Error Analysis| ──> Inductive Qualitative Review (20 Marks)               |
|                     +───────────────────────+                                                           |
+---------------------------------------------------------------------------------------------------------+
```

1. **Unit of Evaluation**: Human-annotated atomic factual propositions extracted from ChatGPT-generated biographical summaries.
2. **Evidence Source**: Wikipedia passages retrieved using BM25 ranking for each fact.
3. **Classification Objective**: Predict whether each atomic proposition is **Supported (`S`)** or **Not Supported (`NS`)** based exclusively on the retrieved Wikipedia evidence.
4. **Official Driver Label Mapping**:
   The raw dataset contains three human annotations: `S` (Supported), `NS` (Not Supported), and `IR` (Irrelevant). The supplied evaluation harness (`factchecking_main.py`) unconditionally maps `IR` to `NS`:
   $$\text{Converted Evaluation Label} = \begin{cases} \text{"NS"}, & \text{if } \text{label} = \text{"IR"} \\ \text{label}, & \text{otherwise} \end{cases}$$
   All classifiers must strictly predict `"S"` or `"NS"`. Outputting `"IR"` is an immediate classification error.

### 3.1 Key Structural Findings & Theoretical Limits
1. **Full Retrieval Pool vs. Evaluation Cache**:
   `data/passages_bm25_ChatGPT_humfacts.jsonl` contains 5,427 retrieval records and 23,720 passage entries for the broader benchmark. When parsed into a lookup dictionary keyed by fact text, it yields 5,373 unique fact query strings.
2. **Evaluated Development Set**:
   `data/dev_labeled_ChatGPT.jsonl` contains 31 biography articles comprising 221 atomic fact instances. When `IR` is mapped to `NS`, the target distribution is 112 `S` (50.68%) and 109 `NS` (49.32%), representing an almost perfectly balanced binary classification task.
3. **The Duplicate Claim Anomaly**:
   The claim `"Cleveland is in Ohio."` occurs twice with identical text and identical retrieved passages:
   - Instance 1 (under Marianne McAndrew): Labeled `IR` (mapped to `NS`).
   - Instance 2 (under Mike Trivisonno): Labeled `S`.
   Because any deterministic model produces identical predictions for identical inputs, it will inevitably misclassify one instance. The theoretical maximum achievable accuracy on this development set is therefore:
   $$\text{Accuracy}_{\max} = \frac{220}{221} \approx 99.5475\%$$
4. **Extreme Length Asymmetry**:
   - Atomic facts: Mean length = **6.76 words** (Min: 4, Max: 14, Median: 7.0).
   - Retrieved passages: Mean length = **141.13 words** (Min: 2, Max: 211, Median: 167.0).
   Passages are on average $\approx 20.9\times$ longer than the atomic claims. Symmetric similarity metrics (Jaccard, Dice, TF Cosine) will be heavily penalized by the passage vocabulary flooding the denominator.

## 4. Framework Architecture & Single-File `factcheck.py` Design

### 4.1 Framework Immutability Boundaries
- **`factchecking_main.py`** [READ-ONLY]: The official driver. Loads data, invokes `predict()`, and prints evaluation metrics. It will **not** be modified, monkey-patched, or bypassed.
- **`data/factcheck.py`** [READ-ONLY]: Original starter code, preserved strictly as an immutable reference.
- **`data/*.jsonl`** [READ-ONLY]: Benchmark datasets and license. Kept untouched.
- **`requirements.txt`** [READ-ONLY]: Environment specification. All code will run on the specified versions.
- **`factcheck.py`** (Root) [ONLY MODIFIABLE FILE]: Contains all custom classifiers, preprocessing helpers, inference engines, and experimental routines.

### Phase 3: Task 1 — Word Overlap Fact-Checking (40 Marks)
- **Objective**: Design, implement, ablate, and optimize a bag-of-words lexical classifier that exceeds the mandatory $\ge 75\%$ accuracy threshold.
- **Core Concepts**: Asymmetric coverage, morphological normalization, stopword filtering, entity/number preservation, evidence aggregation, systematic threshold search, grouped validation.
- **Detailed Implementation Activities**:
  1. *Controlled Preprocessing Ablation Pipeline*:
     - **P0 (Raw Tokens)**: Alphanumeric regex `\b[a-zA-Z0-9]+\b`, lowercased, punctuation stripped, no stopword removal, no stemming.
     - **P1 (Stopword Filtered)**: P0 with NLTK English stopwords removed.
     - **P2 (Stopwords + Stemming)**: P1 with Porter Stemming applied.
     - **P3 (Stopwords + Lemmatization)**: P1 with WordNet Lemmatization applied.
     - **P4 (Number & Entity Aware)**: Preserves numerical tokens (years, quantities); checks if numbers in the claim appear in the candidate passage; applies an empirical penalty factor if missing.
  2. *Lexical Similarity Metrics (Exact Mathematical Formulations)*:
     - **Asymmetric Word Recall**:
       $$\text{Recall}(F, P) = \frac{|\text{Tokens}(F) \cap \text{Tokens}(P)|}{|\text{Tokens}(F)|}$$
     - **Jaccard Similarity**:
       $$\text{Jaccard}(F, P) = \frac{|\text{Tokens}(F) \cap \text{Tokens}(P)|}{|\text{Tokens}(F) \cup \text{Tokens}(P)|}$$
     - **Dice Coefficient**:
       $$\text{Dice}(F, P) = \frac{2 \cdot |\text{Tokens}(F) \cap \text{Tokens}(P)|}{|\text{Tokens}(F)| + |\text{Tokens}(P)|}$$
     - **Term Frequency (TF) Cosine Similarity**:
       $$\text{TF-Cosine}(F, P) = \frac{\mathbf{v}_F \cdot \mathbf{v}_P}{\|\mathbf{v}_F\|_2 \|\mathbf{v}_P\|_2}$$
       *(Designated as TF Cosine, avoiding inaccurate "TF-IDF" references unless inverse document frequencies are explicitly computed).*
  3. *Evidence Aggregation Experiments*:
     - Max-pooling across passages: $\text{Score}(F) = \max_{P \in \text{Passages}} \text{Sim}(F, P)$.
     - Average-pooling across passages: $\text{Score}(F) = \frac{1}{K} \sum_{k=1}^K \text{Sim}(F, P_k)$.
     - Passage concatenation: $\text{Score}(F) = \text{Sim}(F, \bigcup_{k} P_k)$.
  4. *Systematic Threshold Search & Grouped Cross-Validation*:
     - Sweep threshold $\theta \in [0.10, 0.95]$ in increments of $0.01$ on development data.
     - Perform **Grouped 5-Fold Cross-Validation** (grouped by the 31 biography topics) to evaluate threshold stability across unseen biographical subjects and test for potential overfitting.
  5. *Classifier Implementation*:
     - Implement `WordRecallThresholdFactChecker.predict(fact, passages)` applying the empirically selected preprocessing, metric, aggregation, and threshold $\theta^*$.
- **Experiments & Comparisons**:
  - Experiment 1: Preprocessing ablation (P0 vs. P1 vs. P2 vs. P3 vs. P4) under consistent metric and aggregation conditions.
  - Experiment 2: Metric comparison (Word Recall vs. Jaccard vs. Dice vs. TF Cosine) across candidate threshold grids.
  - Experiment 3: Aggregation comparison (Max vs. Average vs. Concatenation).
  - Experiment 4: Threshold sensitivity sweep ($\theta \in [0.10, 0.95]$).
  - Experiment 5: Grouped 5-fold cross-validation across biography topics.
- **Metrics to Calculate**:
  - Development Accuracy, S-Precision, S-Recall, S-F1, NS-Precision, NS-Recall, NS-F1, Confusion Matrix, and Mean Out-of-Fold Cross-Validation Accuracy.
- **Genuine Evidence to Generate**:
  - `task1_preprocessing_ablation.png`: Bar chart comparing accuracy and F1 across configurations P0–P4.
  - `task1_metric_comparison.png`: Comparison chart showing peak accuracy for Word Recall, Jaccard, Dice, and TF Cosine, annotated with the $75\%$ target line.
  - `task1_threshold_tuning_curve.png`: Dual-axis plot of accuracy, S-F1, and NS-F1 across the threshold sweep $\theta \in [0.10, 0.95]$.
  - `task1_score_separability.png`: Histogram / density plot showing the distribution of overlap scores for ground-truth `S` vs. `NS` claims.

  - `task1_confusion_matrix.png`: Heatmap of the final confusion matrix for the chosen Word Overlap classifier.
- **Verification Procedures**:
  - Verify that the chosen configuration achieves $\ge 75.0\%$ accuracy on the development set.
  - If below target, execute the diagnostic protocol: inspect error cases, adjust preprocessing/threshold, and rerun without hardcoding numbers.
- **Completion Criteria**:

### Phase 5: Task 2 — Textual Entailment using DeBERTa-v3 (40 Marks)
- **Objective**: Implement, optimize, and evaluate a deep transformer NLI fact-checker using DeBERTa-v3, incorporating sentence splitting, lexical pruning, decision calibration, and robust memory safety, targeting $\ge 83\%$ accuracy.
- **Core Concepts**: Premise-hypothesis NLI formulation, cross-encoder self-attention, sentence boundary segmentation, lexical evidence pruning, decision boundary calibration, CPU memory lifecycle management.
- **Detailed Implementation Activities**:
  1. *Model Label Mapping Verification*:
     - Verify mapping for `MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli`:
       $$\text{Index 0} \rightarrow \text{entailment}, \quad \text{Index 1} \rightarrow \text{neutral}, \quad \text{Index 2} \rightarrow \text{contradiction}$$
  2. *Group A: Evidence Preprocessing Experiments*:
     - Full passages (unsegmented baseline).
     - Individual sentences (spaCy sentence segmentation + regex fallback).
     - Context-preserving 2-sentence sliding windows (evaluating sentence pairs $[S_i, S_{i+1}]$ to maintain local coreference context).
     - Title-prepended sentence context (evaluating `"Title: " + sentence`).
  3. *Group B: Binary Decision Strategy Experiments*:
     - Strategy 1 (Discrete Argmax): $\hat{y} = \text{"S"}$ if $\operatorname{argmax}(\mathbf{p}) = 0$ (entailment), else $\text{"NS"}$.
     - Strategy 2 (Probability Thresholding): $\hat{y} = \text{"S"}$ if $p_{\text{ent}} \ge \tau$, else $\text{"NS"}$.
     - Strategy 3 (Margin Scoring): $\hat{y} = \text{"S"}$ if $(p_{\text{ent}} - p_{\text{contra}}) \ge \tau$, else $\text{"NS"}$.
  4. *Group C: Lexical Pruning Experiments*:
     - Baseline: No pruning ($\gamma = 0.0$).
     - Pruning threshold sweep: $\gamma \in [0.05, 0.10, 0.15, 0.20, 0.25, 0.30]$.
     - Candidate limits: Evaluate top-$k$ candidates ($k \in [1, 3, 5, \text{all}]$).
     - Pruning fallback policy: Compare retaining the single highest-overlap sentence when all candidates fall below $\gamma$ vs. immediately predicting `"NS"`.
  5. *Group D: Computational Efficiency & Scalability Experiments*:
     - Separately measure and record:
       1. Candidate evidence units generated.

## 6. Technical Risks, Constraints & Mitigation Strategies

| Risk / Constraint | Severity | Technical Description | Concrete Mitigation Strategy |
| :--- | :---: | :--- | :--- |
| **CPU Inference Latency** | **HIGH** | Evaluating DeBERTa-v3 across 221 facts $\times \approx 3.13$ passages on CPU can be computationally slow if unpruned. | Task 2 Group D efficiency experiments will benchmark candidate pruning thresholds ($\gamma$) and batch sizes ($B$) to find the optimal trade-off that maintains accuracy while minimizing CPU latency. |
| **Out-of-Memory (OOM) Errors** | **HIGH** | Accumulating PyTorch tensors across hundreds of forward passes can cause memory exhaustion on limited machines. | Wrap all inference in `with torch.no_grad():`, explicitly delete intermediate tensors (`inputs`, `outputs`, `logits`), and call `gc.collect()` after each forward pass. |
| **The Duplicate Claim Anomaly** | **MEDIUM** | `"Cleveland is in Ohio."` appears twice with conflicting gold labels (`IR`/`NS` vs. `S`). Theoretical max accuracy is $99.55\%$. | Explicitly document this benchmark artifact in the dataset analysis and Task 3 error review. Accept that any deterministic model will mispredict one instance. |
| **Context Loss from Sentence Splitting** | **MEDIUM** | Splitting Wikipedia passages into isolated sentences can detach pronouns (*"He"*, *"She"*, *"It"*) from their named entity antecedents. | In Task 2 Group A, evaluate context-preserving 2-sentence sliding windows and title-prepended sentences alongside isolated sentences to measure empirical context recovery. |
| **Absence of Separate Test Set** | **LOW** | Coursework uses only the development set for evaluation. | Grouped 5-Fold Cross-Validation (by the 31 biography topics) will be conducted as a supporting validation procedure to evaluate threshold stability across unseen subjects before freezing the final development-set model. |
